## 一、产品概述

### 1.1 一句话定位

**Chord 是一个可自托管的中文实时聊天社区产品**——Discord 的核心体验（服务器→频道→消息），
以轻量、可私有部署、中文优先为差异点，服务游戏开黑、兴趣社群、小团队协作三类场景。

### 1.2 目标用户与核心场景

| 用户群体 | 典型场景 | 关键诉求 |
|---|---|---|
| 游戏/开黑社群 | 组队约战、语音开黑、战队频道 | 低延迟消息、在线状态、语音（规划中） |
| 兴趣/粉丝社群 | 话题讨论、公告发布、同人分享 | 频道分组、@提及、表情回应、图片分享（规划中） |
| 小团队/项目组 | 轻量协作、信息同步 | 私信、消息搜索（规划中）、无需公网暴露的自托管 |

### 1.3 产品原则

1. **开箱即用**：一条命令部署，客户端打开即连默认服务器，无需配置
2. **轻量无依赖**：前端不使用平台插件（保 Windows/Android 构建简单）；后端静态编译单二进制
3. **中文优先**：内置中文字体、中文界面与文档
4. **渐进增强**：Redis 可选（缺失自动降级单机模式），不上来就要求重运维

### 1.4 名词表

| 名词 | 定义 |
|---|---|
| 服务器（Guild） | 一个社群容器，内含频道分组与频道 |
| 频道（Channel） | 服务器内的对话空间，归属某个分组（信息/闲聊/技术…） |
| 私信（DM） | 两个用户间的独立会话空间 |
| 邀请码 | 加入服务器的凭证（示例演示码 `demo2024`） |
| presence | 在线状态，Redis 键 `presence:<uid>` TTL 60s 心跳续期 |

## 二、当前版本功能规格（v1.0.0，已上线）

> ✅ = 已实现并经线上验证（2026-11-15 公网端到端验证：注册/登录/实时消息/发送回显均通过）

### 2.1 账号体系 ✅

| 项 | 规格 |
|---|---|
| 注册 | 用户名 + 密码；服务端 bcrypt 加盐存储；用户名唯一（含 4 位 discriminato，如 alice#1001） |
| 登录 | 签发 JWT（HS256，过期 30 天）；token 客户端持久化（桌面 JSON 文件 / Web localStorage / 移动 SharedPreferences） |
| 密钥管理 | JWT 密钥首次启动自动生成，持久化于 `server/.data/jwt_secret`（权限 600，绝不入库/上传） |
| 鉴权方式 | REST 走 `Authorization: Bearer`；WS 走 `?token=` 查询参数（连接时校验） |

**用户故事**：作为新用户，我打开任意客户端，30 秒内完成注册并进入聊天。
**验收标准**：注册→登出→重登，token 失效后历史不丢；服务端重启后已签发 token 仍有效。

### 2.2 服务器与邀请 ✅

- 创建服务器（创建者即为 owner）；邀请码加入；成员列表含在线/离线分区
- 演示数据 seed（`SEED_DEMO=true` 且空库时自动写入 alice/bob/carol + 演示服务器 + 频道 + 历史）
- **限制**：仅 owner/member 两级权限（见 ROADMAP v1.1 角色体系）

### 2.3 频道 ✅

- 分组（信息/闲聊/技术…）+ 频道两级结构；频道内消息独立分页
- 界面：PC 四栏布局（服务器图标栏/频道栏/消息区/成员栏），窄屏/手机单栏 + 抽屉

### 2.4 消息 ✅

| 项 | 规格 |
|---|---|
| 发送 | REST 写入（可靠、可校验），结果以 WS 事件广播（含作者本人），客户端按消息 ID 去重 |
| 历史 | 分页游标 = 消息 UUIDv7 ID（时间有序），`WHERE id < cursor` 向前翻页 |
| 编辑/删除 | 作者本人可编辑/删除；删除为软删除或物理删除（以服务端实现为准） |
| 富文本 | Markdown-lite 渲染（粗体/斜体/代码/链接等子集）；@提及高亮 |
| 表情回应 | 消息级 emoji 回应，点击增减 |
| typing 提示 | 输入中状态实时广播 |

**验收标准**：双客户端登录不同账号，A 发消息 B 1 秒内可见；编辑/删除同步；断线重连后不重复不丢失。

### 2.5 私信 DM ✅

用户列表发起会话，与频道消息同一套消息管线，未读独立计数。

### 2.6 在线状态与未读 ✅

- presence：WS 心跳（25s）续期；单实例用进程内连接表，多实例用 Redis 兜底跨实例感知
- 未读数与 @提及数按频道累计，进入频道清零
- 成员列表实时反映在线/离线（线上已验证：alice 在线绿点，bob/carol 离线）

### 2.7 多端分发 ✅

| 端 | 形态 | 分发渠道 |
|---|---|---|
| Web / PWA | Flutter Web（CanvasKit 渲染器，**禁止用 --wasm 构建**，见踩坑记录） | http://129.226.159.168:3000 + Release 附件 |
| Windows 桌面 | 原生窗口 1200×800，托盘最小化 | Release `chord-windows-x64.zip` |
| Android | APK（arm64/armv7/universal，release 暂用 debug 签名） | Release 附件 |
| 服务管理控制台 | Laragon 风格托盘程序（仅 Windows，本机部署用） | 仓库构建产物 |

默认服务器地址规则：Web 从页面 URL 推导（同主机：8081）；桌面/移动由构建参数
`--dart-define=CHORD_DEFAULT_BASE=` 指定（当前构建指向新加坡服务器）；登录页均可手改。

### 2.8 服务端架构规格 ✅

- **技术栈**：Go 1.27（Gin + gorilla/websocket + GORM/MySQL 8 + go-redis）
- **端口**：API 8081；Web 静态托管（serveweb）3000
- **事件总线** `bus.Bus` 抽象：MemoryBus（单实例进程内）/ redisBus（pub/sub `chord:events`）同接口；Redis 连不上自动降级
- **CORS**：`CLIENT_ORIGIN` 白名单 + 本地默认来源；WS 不校验 Origin（鉴权靠 token）
- **部署**：`deploy/install.sh` 一键安装（systemd 双服务 chord-server/chord-web，幂等）；
  `deploy/update.sh web|full` 从 GitHub Release 拉取更新
- **当前生产实例**：新加坡腾讯云 129.226.159.168（MySQL/Redis 本机直连，DB `chord`）

## 三、非功能规格

### 3.1 性能

| 指标 | 现状 / 目标 |
|---|---|
| 消息端到端延迟（同机房） | 实测亚秒级；目标 <300ms P95 |
| Web 首屏 | ⚠️ 现状约 10MB 资源未压缩，跨境首载 2-5 分钟；**v1.1 必须上 gzip/brotli + CDN**（目标 <10s） |
| WS 心跳 | 25s 客户端心跳，指数退避重连 |
| 容量基线 | 单实例（2C4G 级）目标 500 在线连接、100 万消息；超出需多实例 + Redis bus |

### 3.2 安全

- 密码 bcrypt；JWT HS256 30 天；密钥文件 600 权限
- **已知短板（ROADMAP 高优先）**：当前明文 HTTP，密码裸奔传输——公网正式使用前必须上 TLS 反代
- WS Origin 不校验（token 即身份），带宽放大风险低但需关注
- rate limit：暂无（v1.1 加基础限流：注册/登录/发消息频控）

### 3.3 兼容性

- Web：Chrome/Edge/Firefox/Safari 近两年版本（CanvasKit 要求 WebGL）
- Android：API 21+（Flutter 默认 minSdk）；Windows：Win10/11 x64
- 数据库：MySQL 8（utf8mb4）；GORM 自动迁移

### 3.4 可运维性

- systemd 常驻 + journalctl 日志；`redisprobe` 状态探针
- 一键安装/更新脚本幂等；`chord.sh`（Git Bash）本地开发三件套
- 数据备份：MySQL 导出即可全量恢复；唯一秘密文件 `.data/jwt_secret` 需备份

## 四、已知限制（公开承认的边界）

1. 无单元测试/集成测试；质量靠 `scripts/guitest` 黑盒走查（双账号实时消息、双视口截图）
2. 权限仅 owner/member 两级
3. 消息正文纯文本（无附件/图片）
4. 无消息搜索、无推送通知（依赖前台在线）
5. Android release 为 debug 签名；Windows 无代码签名（SmartScreen 会警告）
6. 单实例架构（多实例能力已具备：redisBus + presence 兜底，但未部署验证）
7. 明文 HTTP，无 TLS

## 七、风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 明文 HTTP 期间账号被盗用/嗅探 | 高 | v1.1 TLS 为最高优先；期间建议仅熟人圈使用 |
| 服务器跨境带宽小，大文件上传拖垮实例 | 中 | 上传限速/限额；图片走 CDN；超过阈值换对象存储 |
| 单实例故障全站不可用 | 中 | systemd 自动重启；数据库定期备份；多实例为 v2 项 |
| debug 签名 APK 被安全软件拦截 | 低 | v1.2 配正式 keystore 签名 |
| 无自动化测试，回归靠手工 | 中 | v1.1 起 Go httptest + Flutter widget test 基建，核心路径必覆盖 |
